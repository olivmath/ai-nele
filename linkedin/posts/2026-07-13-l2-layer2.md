"Grande parte das L2 do Ethereum existe porque a Layer 1 não consegue entregar a experiência que gostaríamos."

- Ou seja: GAMBI.

Bom, mas o que é uma L2?

Na verdade, uma Layer 2 é um padrão de arquitetura, não uma tecnologia do Ethereum.

Na Web2, quando um sistema começa a crescer, normalmente fazemos algo parecido:

- Banco de dados principal
- Cache (Redis)
- CDN
- Filas (Kafka/RabbitMQ)
- Read Replicas
- Microserviços

Pois é...

Quase ninguém resolve problemas de escalabilidade colocando uma CPU maior no servidor ou mexendo apenas no monólito principal.

A gente cria camadas.

No mundo blockchain acontece exatamente a mesma coisa.

Uma Layer 1 continua sendo responsável pela segurança, consenso e disponibilidade dos dados.

Já a Layer 2 tenta resolver algum problema específico:

→ Escalabilidade
→ Privacidade
→ Custos
→ Experiência do usuário
→ Performance

Dependendo da blockchain, isso pode acontecer de formas completamente diferentes.

- Ethereum → Optimistic Rollups, ZK Rollups e Validiums.
- Bitcoin → Lightning Network.
- Polkadot → Parachains.
- Starknet → uma zkVM inteira.

Todas são camadas adicionais resolvendo problemas específicos.

Percebe como Layer 2 é muito maior do que Ethereum?

Na minha cabeça, faz mais sentido pensar assim:

A Layer 1 é um sistema operacional. A Layer 2 são aplicações de infraestrutura auxiliares.

A mesma ideia existe na Web2 há décadas. A diferença é que, em blockchain, demos outro nome para ela.

Esse foi justamente um dos assuntos que gravei na série de Arquitetura Blockchain. As aulas estão fechadas hoje apenas para os membros da comunidade.

E, depois de mais de 30 dias explicando 30 blockchains diferentes, chegamos à mesma conclusão do Vitalik:

- L2, em grande parte, é um Ctrl+C / Ctrl+V do Ethereum, de forma GAMBI.
